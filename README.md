# Agent Office

[Agent Office](https://github.com/F0gr1/agent-office) と [AI情報リーダー](https://github.com/F0gr1/ai-reader) は、別々のリポジトリで管理します。

```sh
git clone https://github.com/F0gr1/agent-office.git
cd agent-office
git clone https://github.com/F0gr1/ai-reader.git services/ai-reader
```

依頼ごとに社長が必要な担当を選び、利用者のMac上のCodex / Claude Codeで仕事を進めるローカルアプリです。選定理由、作業の動き、担当ごとの成果を確認できます。

## AI情報リーダー

「作成したサービス」からAI情報リーダーを起動し、記事を検索・閲覧できます。Officeは `http://127.0.0.1:4317/`、リーダーは `http://127.0.0.1:4318/` です。OpenAI News・Zenn AI・Zenn LLM・Google AIの公開フィードを起動時／手動操作時に取得します。既読・保存はMac内へ残ります。Xは投稿URLの手動保存のみ、AI要約・定期取得・任意RSSの追加は未対応です。

リーダーは別リポジトリとして `services/ai-reader` に配置します。Officeで起動したプロセスだけを停止・再起動でき、管理外の起動には「開く」だけを提供します。Macアプリの「作成したサービス」から開く場合は標準ブラウザーで表示します。Office終了時にはOfficeが起動したリーダーも終了します。

Officeとリーダーを別々に取得した後、リーダーをこのリポジトリの `services/ai-reader` にcloneしてください。実際のRSSリポジトリURLを `RSS_REPO_URL` に設定し、親リポジトリのルートで `git clone "$RSS_REPO_URL" services/ai-reader`、続いて `npm --prefix services/ai-reader ci --offline --omit=dev` を実行します。既存の開発フォルダーには同名のリーダーフォルダーがあるため、このclone手順は新しく取得したOffice側で実行します。既存フォルダーや保存データは移動・削除しません。親リポジトリは `services/` を追跡しません。リーダーがない場合、Office本体は動作しますが、リーダーの起動・Desktop梱包は案内付きで失敗します。リーダー単独の依存導入・起動・テストはリーダー側READMEを参照してください。`npm run desktop:build` はリーダーを同梱するため、この配置が必要です。

## 新規プロジェクトの準備

画面の「新しい依頼」で種類を「新規プロジェクトの準備」に切り替え、目的と準備先の既存フォルダーを指定します。言語などが未決でも依頼できます。アプリ本体の開発とは分けて、指揮官が必要な担当を選び、AGENTS.mdと必要なプロジェクトSkillsを準備します。

Codexでは `$project-setup`、または「このフォルダーでRSSの開発準備をして」のように依頼します。共通のSkill入口を使う場合は、利用環境に登録してください。手順は [project-setup](skills/project-setup/SKILL.md) にあります。

既存の指示やSkillsを確認し、重複するSkillsは増やしません。X・Zenn等からの候補は紹介元や公式情報を照合し、出典、採否理由、取得できなかった情報を成果に残します。外部情報を毎回取得できる保証はありません。Global設定の書換えや外部サービスの契約はこの準備に含めません。AGENTS.mdは作業ルール、Skillは再利用手順であり、実行時の担当定義とは区別します。

新しいSkillは対象内に草案として保存し、独立レビューと指揮官の承認後にアプリが `.agents/skills` へ配置します。初期対応は手順だけのSKILL.mdです。既存と異なるSkillは上書きせず確認待ちにします。スクリプトや追加資料を伴う外部Skillは、候補と必要な確認を報告します。

## 2026-10-28: 改善画面を通常アプリへ統合

通常の利用・画面修正先は **http://127.0.0.1:4317/** です。4320は改善案を確認するために分けていた試作で、通常アプリではありません。今後のUI変更は `public/` のソースへ行い、`npm run build` で配信用ファイルを更新します。

ホーム、依頼作成、作業詳細、トーク・履歴、社長への相談、成果確認を分け、元の入力と対象をサイドバーに残します。ホームはWebGPUを優先し、WebGL2・担当一覧へ切り替えます。9名の候補は維持し、実際に作業中の担当のみを動かします。

依頼は送信前に対象・入力・成果・完了条件・範囲・履歴参照を確認します。任意項目は `requestContext` に保存して各担当へ渡し、修正依頼でも引き継ぎます。トークはOfficeに記録された入力・担当依頼・担当報告を表示します。指揮官の最終承認と、ユーザーの「成果を受け入れる」の記録は別です。受け入れは完了済み依頼だけに保存できます。

## 2026-10-28: 必要な担当だけを選ぶ

新しい画面と外部依頼入口では、社長が依頼・追加指示・既存成果を確認し、今回必要な担当だけを選びます。仕様・実装・レビュー2名を毎回呼ぶことはありません。社長だけで回答することもできます。継続依頼でも必要性を判断し直します。追加メンバーは候補として登録され、選ばれた依頼だけに参加します。

選定理由と担当への依頼を表示し、呼び出しごとの成果を `tasks` に保存します。初回の社長判断や修正前の成果も残ります。成果一覧から結論・指摘・確認結果・本文を確認、コピーできます。

実装が必要な場合は、社長が独立した確認担当を最低1名選びます。選ばれた確認担当へ同じ実装成果を渡し、他の確認担当の結論を含めず順番に確認します。修正は最大3回で、未解決なら確認待ちです。社長は登録済みモデルや権限を変更しません。不正な選定は停止し、全員参加へ戻しません。

APIに `specialists` 配列を明示する旧方式のみ、以下に記載した固定工程を維持します。旧履歴も保持します。以下の9人体制・レビュー2名の説明は旧方式のものです。`specialists` を省略する新しい既定動作は自動選定です。

## Codexの指示からAgent Officeへ渡す

2026-10-29の設定により、このプロジェクトでは今後の依頼・質問を原則Officeへ渡し、Codexが受付・追跡・結果の取りまとめを行います。方針は `AGENTS.md`、具体的な手順は `skills/agent-office/SKILL.md` に保存しています。Office内の担当にはこの転送ルールを適用せず、環境変数とCLIのガードで再転送を防ぎます。停止・状況照会・連携の修理や、ユーザーが明示した直接実行は例外です。他プロジェクトの既定動作は変更しません。

Macアプリがある場合は優先して起動し、受け付けた依頼IDの画面を開きます。アプリ未作成ならブラウザーへ切り替えます。既存依頼を開くだけなら `--show RUN_ID`、Office全体の状態は `--state`、指定依頼の詳細は `--status RUN_ID`。状態の取得では新しいAI実行を作りません。

依頼をUTF-8ファイルへ保存し、次の入口で送信できます。アプリが停止中なら起動し、依頼IDと該当画面のURLを返します。Macでは画面も開きます。起動前に `npm run build` が必要です。

```sh
node scripts/office.mjs --workspace /absolute/project --instruction-file /absolute/request.txt
```

画面を開かない場合は `--no-open`、別ポートは `--port 4319` などを指定します（4318はリーダー用）。結果の再取得と継続依頼は次のとおりです。

```sh
node scripts/office.mjs --status RUN_ID
node scripts/office.mjs --continue RUN_ID --instruction-file /absolute/followup.txt
```

既存のローカルAPIとトークン検証を利用します。トークンは出力・保存しません。送信は1回だけで自動再送しません。応答が途切れた場合は再送前に履歴を確認してください。旧サーバーが動作中なら再起動を案内します。実行中の依頼がある場合は新規依頼を拒否します。

この入口で明示的に渡した依頼がOfficeで動きます。このチャット内部の既存サブエージェント・過去のCodex会話の自動取込や常時同期は未実装です。

## 起動と使い方

### Macアプリ版（2026-10-28）

`dist-desktop/Agent Office-darwin-arm64/Agent Office.app` を開くと、専用ウィンドウで同じ4317を利用できます。ウィンドウを閉じてもアプリと作業は終了せず、メニューバーのアイコンから開き直せます。「Agent Officeを終了」またはCommand+Qで完全終了します。アプリが起動したサーバーで作業中なら中断前に確認します。外部で起動済みのサーバーを再利用した場合、そのサーバーは終了しません。

既定のMac用ビルドは元のプロジェクトの絶対パスを含めず、同梱版と `~/Library/Application Support/Agent Office/` の保存先を使います。既存データの自動移動は行いません。現在の開発用アプリと同じ元フォルダーを優先したい場合だけ `node scripts/package-desktop.mjs --local-source` を明示します。配布ファイルへ履歴・認証情報・登録プロジェクト一覧は含めません。

「ログイン時に起動」はメニューバーから任意で選択します。初期状態では変更していません。既定のビルドはアドホック署名で、配布用のDeveloper ID署名・公証は行っていません。ログイン時起動の反映はmacOSの承認や署名状態に依存します。スリープ・電源断中は作業できません。

開発時は `npm run desktop`、Macアプリの作成は `npm run desktop:build`。初回にElectron本体が未取得なら `npm run desktop:install-runtime` を実行します。独立した起動確認は常駐アプリを終了した状態で `npm run desktop:smoke` を使います。`npm run desktop:build` は既定で元フォルダーを参照しません。開発用の元フォルダー優先ビルドには `npm run build` 後に `node scripts/package-desktop.mjs --local-source` を使います。Intel Mac・他のMacは未検証です。

1. `start.command` をダブルクリック。Node.js 22以降と、ログイン済みCodex CLIが必要です。
2. http://127.0.0.1:4317 を開きます。
3. 「新しい依頼」でCodex登録プロジェクトを選び、指示を入力して「チームに依頼する」を押します。選択したフォルダのコード・資料・AGENTS.md・AGENTS.local.mdを参照し、実装担当が編集します。既定はアプリ内の専用workspaceです。「別のフォルダを指定」なら絶対パスを入力できます。
4. 部屋をクリックすると担当・モデル・進捗・出力・未解決の指摘・確認結果が表示されます。
5. 「この実行を中止する」で停止できます。すでに加えたファイル変更は残ります。

起動中はターミナルを開いておいてください。終了はControl+Cです。ポートを変更する場合は `PORT=4319 node server.mjs` で起動します（4318はリーダー用）。

## 仕事の流れ

指揮官の指示整理 → 調査 → PGの仕様作成 → 設計 → UI/UX → PG2の実装・テスト → QA → 2人の独立レビュー → 指揮官の最終照合。

調査・設計・UI/UX・QAは依頼ごとに参加を選べます。選択しない担当は実行せず、旧5人体制の履歴も未参加と表示します。UIを含まない依頼ではUI担当が対象外であることを明示します。QAの修正指摘も実装へ戻します。

レビュー担当は同じ仕様・実装報告を受け取り、互いの結論を見る前に確認します。片方でも指摘があれば実装担当へ戻します。最大3回の実装・修正で解決しない場合や情報・権限不足は「確認が必要」で停止します。エラーや中断を完了と扱いません。「完了」はAIによる条件照合であり、人の受入・本番デプロイを意味しません。

| 役割              | スタンダードの指定モデル | 推論強度 | 選定理由                               |
| ----------------- | ------------------------ | -------- | -------------------------------------- |
| 指揮官・モカ      | gpt-6-sol                | high     | 依頼、担当指示、成果の整合性           |
| 調査・ハル        | gpt-6-luna               | high     | 範囲を限定した資料と現状の調査         |
| 設計・レオ        | gpt-6-astra              | medium   | 構成、境界条件と技術リスクの判断       |
| UI/UX・ニコ       | gpt-6-sol                | high     | 画面、操作、アクセシビリティの整理     |
| QA・ユキ          | gpt-6-sol                | high     | 実装と受入条件の独立検証               |
| PG・ミント        | gpt-6-sol                | high     | 調査と具体的な仕様・検証条件の整理     |
| PG2・ピコ         | gpt-6-sol                | high     | ファイルの実装とテストを伴う作業       |
| レビュワー・ルル  | gpt-6-sol                | high     | 仕様との一致と回帰の確認               |
| レビュワー2・ソラ | gpt-6-astra              | medium   | 安全性や境界条件を独立した観点から確認 |

「じっくり確認」は指揮官をgpt-6-astra / highに切り替えます。モデル名は実行に指定した値であり、サービス側の実行モデルを別途証明するものではありません。料金・速度の比較測定はしていません。利用できないモデルはエラーで止まり、無断で置き換えません。

「省トークン」は調査・仕様作成・UI/UXの推論強度だけをmediumにします。モデル、実装、QA、独立レビュー、指揮官の最終判定はスタンダードと同じ指定です。全モードで検索範囲と引継ぎを簡潔にする指示を渡しますが、受入条件や根拠を任意に切り詰めません。実際の削減量はタスクによって異なり、現時点で比較測定はしていません。APIで専門担当を省略すると社長が必要な担当を選びます。

## 実行範囲と保存

- 実際の `codex exec --json` を起動し、実イベントから表示を更新します。シミュレーションはありません。GUIまたは外部依頼入口から開始した依頼が対象です。ほかのCodexチャットの自動追跡は未対応です。
- 編集権限は実装担当のみ `workspace-write`、その他は `read-only`。既存のCodex認証・設定と対象のAGENTS.mdを使用します。承認が必要な操作はこの初版では自動許可せず、実行できない場合は停止します。
- 同時に実行できる依頼は1件。2人のレビューは並列です。既存作業の競合を避けるため、対象フォルダを別のAIと同時に編集しないでください。
- 公開、PR作成、コミット、外部通知は担当指示で対象外としています。ネットワークや連携ツールの権限はCodexの既存設定が適用され、完全な隔離環境ではありません。
- データは `.data/state.json` に保存します。指示・担当成果・時刻を含みます。非公開の推論や生のコマンド出力は保存しません。最新30件を画面に表示し、古い依頼は `.data/archive/` に保存します。
- CLIが完了イベントでトークン使用量を返した場合は、入力・キャッシュ済み入力・出力の実測値を実行全体と担当の最新工程に保存します。値が返らなかった工程の使用量は推定しません。
- アプリ再起動時、途中の依頼は確認待ちになります。自動再開・自動ロールバックはありません。
- ブラウザとサーバーはMac内の127.0.0.1で通信します。認証情報をブラウザへ渡しません。LLM利用の通信は既存Codexの接続先へ行われます。

## 検証

### 修正・追加指示

「最近の依頼」から引き継ぐ依頼を選び、「今の依頼」の「この依頼に修正・追加」を押します。「ピコへ、前回の入力エラーを修正して」のように記入して送信できます。元の依頼、これまでの追加指示、担当ごとの最新成果・仕様・レビュー指摘を引き継ぎ、同じプロジェクト・設定で指揮官から再確認します。後の指示で変更されていない要件は維持します。

実行中の担当へ直接割り込む機能ではありません。完了を待つか中止後に送信してください。中止しても既に行われたファイル変更は戻りません。新しいCLI実行に保存済みの内容を渡す方式で、CLI内部の会話や推論の再開ではありません。自動選定では担当を選び直し、選ばれた確認担当と社長が照合します。旧方式ではレビュー2名と社長の最終OKが必要です。「新しい依頼」のフォームは従来どおり独立した依頼です。

履歴は画面で選べる直近30件から引き継げます。要件と成果の合計が160KBを超える場合は、黙って切り捨てずエラーにします。過去に独立した依頼として送った履歴を自動で結合する機能はありません。

`npm test` で受け渡し、2人のレビュー、差し戻し、異常終了、取消、再起動、停止を無視するプロセスの強制終了を確認します。テスト用の代替実行結果と、実Codexによる動作確認は区別しています。

公式の実行方式: https://learn.chatgpt.com/docs/non-interactive-mode

## 登録プロジェクトの一覧

登録プロジェクトはローカルの `projects.json` に保存します。この実ファイルと `codex-history.json` は公開対象から外し、空の公開例を `projects.example.json` と `codex-history.example.json` に置きます。実ファイルがない場合は空一覧として起動できます。フォルダが存在しない登録は選択不可です。「一覧を再読み込み」は保存済み一覧の再取得であり、Codexからの自動同期ではありません。必要なら例をコピーしてローカル登録を追加してください。過去のCodexチャットやクラウド専用プロジェクトは自動参照しません。

プロジェクト選択と作業フォルダの一致はサーバーが実パスで確認します。プロジェクトを選ぶだけでは実行せず、「チームに依頼する」で初めて作業が始まります。

## ソースの編集と整形

画面処理は `public/main.js`、役職表示は `public/roles.js`、アバターは `public/avatars.js`。`npm run build` で配信用の `public/app.js` を生成します。生成ファイルを直接編集しないでください。`npm run format`、`npm run build`、`npm run format:check`、`npm test` で確認できます。

実行中は再起動せず、終了後に再起動すると節約モードが有効になります。旧サーバーを検知した画面では節約モードを無効にします。

## 3Dオフィス

Three.jsで社長室・企画室・作業部屋・レビュー室を描画します。キャラクターや吹き出しを選ぶと担当詳細が開きます。吹き出しは実際の進捗・担当工程の完了・修正要求・最終承認を区別します。全員の成果は下の一覧・担当詳細から確認できます。3D表示が使えない環境では一覧を利用できます。

3D画面は `public/office-scene.js`、吹き出し判定は `public/speech.js`。`npm run build` はThree.jsを含む `public/app.js` と、`base.css` / `office-scene.css` を結合した `public/styles.css` を生成します。生成ファイルは直接編集しません。依存の復元は `npm ci`。CDNアクセスはなく、アニメーションと吹き出しの表示自体はLLMを呼び出しません。

## 進捗と反復の確認

### 社長室への相談

担当が不明点・障害を報告すると、指揮官が元の依頼・既存成果・権限の範囲を確認し、対応指示を作成します。相談元のアバターが社長室へ移動し、オフィスの下に理由と対応指示を表示します。相談への返答は依頼全体の最終OKではありません。

調査・設計などで後工程へ渡せる未確認事項は、指揮官の指示とともに引き継ぎます。仕様書は合格が必要です。実装・検証の障害は指示に従って再確認し、レビュー2名と最終指揮官の確認を省略しません。相談のための指揮官呼び出しは1依頼につき最大2回です。権限・情報・環境の準備が必要な場合や同一失敗の反復は、対応待ちになります。

既に止まった履歴は自動実行しません。「社長室への相談を入力する」から内容を確認して継続依頼を送ってください。既存の権限やネットワーク制限を指揮官が解除する機能ではありません。

担当のゴールと現在の処理を分離して表示します。検索・資料確認・テストなどを開始/終了イベントで区別し、終了後は次の更新待ちになります。複合コマンドなど分類が不確かなものは汎用のコマンド表示です。担当時間、実行中の処理時間、完了件数、最終イベント受信からの時間を表示します。90秒更新がない場合は継続状況を未確認と案内しますが、時間だけで異常とは判定しません。

同一コマンド・終了コード・出力の失敗が3回連続すると停止し「確認が必要」にします。比較にはメモリ内のハッシュのみを使い、コマンドや出力の原文は保存しません。成功、異なる結果、ファイル変更で連続数をリセットし、rg/grepの該当なし（終了コード1）は失敗反復に含めません。並列レビューで検出した場合は他方も中止します。この検知は完全な無限ループ検出ではなく、意味が同じでも表記・出力が異なる反復は検出しない場合があります。

修正前の履歴は開始/終了が同じ文言で保存されており、過去の反復の有無は再構成できません。進捗は新しく開始する依頼から記録されます。内部の推論内容やコマンド出力は表示しません。

## 工程図と広い部屋

### アプリ本体が管理する実行環境

各担当の起動前に、アプリ本体が共通作業ログを保存し、対象内の `dist/index.html` があれば静的プレビューを用意します。担当にこのURLと保存結果を渡すため、読み取り専用担当がログを書いたり、サンドボックス内でHTTP待受を始めたりする必要はありません。実装後のビルドは次工程の準備時に配信対象になります。ソース変更後はプロジェクトのビルドが必要です。

プレビューは `127.0.0.1` の空きポートを自動選択し、ビルド済み `dist` のみを別オリジンで配信します。対象外へのリンク、隠しファイル、ソースマップは配信しません。任意コマンドの実行、外部公開、担当の権限拡大は行いません。SSRなど静的dist以外の起動方式は未対応です。アプリ再起動時はURLを無効化し、次の実行時に再準備します。

ログはアプリ本体が `~/Projects/.ai-worklog/YYYY-WW.md` に実行単位で作成・更新します。依頼の原文やソースを保存せず、保存失敗は明示します。プレビュー配信成功だけで表示検証を合格にせず、ブラウザの確認は担当が行います。

オフィスの上のフローチャートで現在の工程、並行レビュー、修正・相談・対応待ちを確認できます。工程を押すと担当詳細を開きます。工程完了と指揮官の最終OKは別に表示します。切断時は最後に取得した情報であることを表示します。

各部屋は縦横約25%拡張し、机とアバターを配置し直しました。中程度の画面幅では担当詳細を下段へ移し、オフィスの表示幅を広げています。

## 接続・エージェント設定

左メニューの「接続・エージェント設定」から、Codex CLI / Claude Codeのインストール・ログイン状態を確認し、担当ごとのAI・モデル・推論強度、名前、役職、役割説明、追加指示を編集できます。認証情報は保存せず、各CLIの既存ログインを利用します。未導入の場合は画面の公式セットアップ手順から導入・ログインし、「接続を確認」を押します。

Officeスキルは設定画面で独立して作成・編集・有効化し、担当ごとに割り当てます。保存後の新規依頼では開始時の定義と版を固定し、有効な指示を担当プロンプトへ追加します。適用記録は呼び出しごとの成果に表示します。「プロンプトへ適用」はモデルの遵守や外部CLIスキルの実行を保証しません。無効・参照不能・旧履歴の適用記録なしは区別して表示します。

作業詳細には呼び出しIDごとの指示、状態、報告、実際に参照された入力元と受け渡し先を表示します。トークと成果へ同じIDで移動できます。構造化された確認結果は確認済み・未確認・失敗に分け、従来の自由文 `checks` は「区分未記録」と表示します。依頼の完了とユーザーの受入は別の状態です。

描画方式は画面で自動またはWebGL2指定を選べます。実際に使われた方式は3D画面内に表示されます。`npm run build` は通常配信用の `public/app.js`・`public/styles.css` と、次工程の静的プレビュー用 `dist/index.html`・`dist/app.js`・`dist/styles.css` を生成します。

「メンバーを追加」で最大20名（既存9名＋追加11名）まで登録できます。追加担当は実装前の専門確認または追加レビューの候補として登録され、3Dオフィスにも追加席が表示されます。選定された追加レビューの合格も最終承認条件です。設定は `.data/settings.json`（OFFICE_DATA_DIR設定時はその配下）に保存され、次の依頼・継続依頼から適用。進行中は開始時の設定を保持し、過去履歴の役割表示も保存した設定を使います。

Claude連携は作業フォルダ内の読み取りツール、実装担当は追加で編集ツールに限定。コマンド実行・ブラウザ検証は利用しません。テスト実行を要する担当はCodexを選ぶか、実行可能な担当・環境で別途検証します。Claudeの実サービス接続は利用環境で確認してください。モデル利用可否はログイン先の契約に依存します。
